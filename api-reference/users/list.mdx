## Endpoint

```text
GET /api/v1/users/
```

## Headers

<ParamField header="api-key" type="string" required>
  Your application API key
</ParamField>

<ParamField header="secret-key" type="string" required>
  Your application secret key
</ParamField>

## Query Parameters

<ParamField query="is_active" type="boolean">
  Filter users by their active status. If not provided, returns all users.
</ParamField>

<ParamField query="limit" type="number">
  Opt into pagination: return at most 1–1000 users. Omit this parameter to keep
  the existing full-list behavior.
</ParamField>

<ParamField query="offset" type="number" default="0">
  Number of matching users to skip; must be zero or greater.
</ParamField>

<ParamField query="search" type="string">
  Case-insensitive literal substring search across user ID, app_user_id, name,
  email, phone and username. Maximum 200 characters; surrounding whitespace is
  ignored. Search the full matching list, not just the returned page.
</ParamField>

<ParamField query="include_summary" type="boolean" default="false">
  Return X-Total-Count and X-Active-Count response headers for the full matching
  list, after status/search filters and before pagination.
</ParamField>

## Pagination compatibility

The body remains an array, not a new pagination object. With `limit`, results
are ordered by creation time descending, then ID descending to break ties.
An empty or out-of-range page returns `[]`. Records can change between requests,
so pagination is not a snapshot or a replacement for a bulk export.

Use `?limit=50&offset=0&include_summary=true`, then increment `offset` by 50.
Invalid limits, negative offsets or searches longer than 200 characters return
HTTP 422. Existing requests without the new options remain full-list reads.
Deploy the wallet API update before using these options in your dashboard.

## Response

The response is an array of user objects.

<ResponseField name="id" type="string">
  Unique identifier for the user
</ResponseField>

<ResponseField name="app_user_id" type="string">
  The user ID from your own application
</ResponseField>

<ResponseField name="name" type="string">
  User's full name
</ResponseField>

<ResponseField name="email" type="string">
  User's email address
</ResponseField>

<ResponseField name="phone_number" type="string">
  User's phone number
</ResponseField>

<ResponseField name="is_active" type="boolean">
  Whether the user account is active
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of creation
</ResponseField>

<RequestExample>

```bash cURL
curl --request GET \
  --url 'https://hpay-api.host-sl.com/api/v1/users/?is_active=true' \
  --header 'api-key: YOUR_API_KEY' \
  --header 'secret-key: YOUR_SECRET_KEY'
```

```python Python
from hostpay import HostPay

client = HostPay(api_key="YOUR_API_KEY", secret_key="YOUR_SECRET_KEY")

users = client.users.list(is_active=True)
for user in users:
    print(user["id"], user["name"])
```

```typescript TypeScript
import { HostPay } from "@hostpay/sdk";

const client = new HostPay({ apiKey: "YOUR_API_KEY", secretKey: "YOUR_SECRET_KEY" });

const users = await client.users.list({ isActive: true });
for (const user of users) console.log(user.id, user.name);
```
